### What the investigation established (read-only; three parallel code/history/test audits + log forensics)

**1. This is NOT a 1.7.0 regression. It is the 2026-07-29 RCA's own unfinished residual.**
- `src/dns_governor.rs` has **one commit ever** (`465ed5c`, 2026-07-26). `src/dns.rs`'s ladder/breaker logic last changed in `d646b7c` (2026-07-29); `0388a7e` (08-16) touched only P2.11/P1.7/P2.10b (root-race gating, negative memo, CNAME-from-TXT).
- `d646b7c`'s commit body (the **only** place this number exists — stripped from CHANGELOG 1.6.1:70, absent from ISA.md): *"Depth-3 still causes transient flapping while running (48% of samples, recovering immediately) — real, and not yet localized: a depth-2 bisect with each subsystem isolated came back completely clean, so it needs depth-3-scale arms to reproduce."*
- Re-measured and never localized: 08-13 on 1.6.2 (343 "All DNS resolution failed" WARNs; 13× DoH-blocked → 9× DoT-blocked → 7× no-transport — roadmap `:364`), 08-18 on 1.7.0 (47%: 19,837/42,174; 8× DoH / 13× DoT / 3× UDP demotions), 08-19 on 1.7.0 (60%).
- Roadmap P2.10a (unbind the 50-QPS DNS bucket) is explicitly **owner-gated on closing this investigation** (`Plans/deep-scan-optimization-roadmap.md:182,364`).

**2. The "blocked" declarations are false positives.** Probed at idle on this network today: DoT to 1.1.1.1/8.8.8.8/9.9.9.9:853 all TLS-OK; UDP/53 direct and via 192.168.1.1 fine; DoH 1.1.1.1 and 8.8.8.8 answer in 70–90 ms. Yet the 08-18 `-v` log shows **DoT declared "blocked after 8 consecutive failures" at T+26s, T+40s, T+41s** and UDP/53 at T+23s; at T+20min all three tiers were down simultaneously ("no DNS transport currently reachable"). Names that certainly resolve — shopify.com, linkedin.com, zoom.com, calendly.com, chargebee.com — logged "All DNS resolution failed."

**3. Seven coupled defects, each with a file:line anchor (verified by the audit; the fix design below cites them as A–G):**

|---|---|---|---|

**4. Why four releases of tests did not catch it.** The 95% coverage gate is measured against a `--cfg coverage` build in which every DoH network fn, the retry/backoff policy (`resilient_attempts`, `in_race_backoff`), `laddered_direct`, the memo block, and `settle_arm` are stubs or absent — and all 77 wiremock tests are compiled out. No test drives the governor under sustained concurrent load (the one concurrent test pins it). No test asserts a failure-RATE bound. wiremock latency/flapping/timeout injection is never used for DNS (`tests/common/wiremock_helpers.rs` has a `mock_timeout_server` but no test declares `mod common;`). No CI job runs a scan or scheduled DNS check. Three `tests/dns_*` files have zero assertions. The repo's own CLAUDE.md already states the lesson: *"Unit tests validate mechanisms; only a scan validates magnitudes and wiring under contention."*

**5. Why every incident is unreconstructable.** A default scan persists **no** DNS diagnostics: the governor line, `DNS Failures`, the coverage manifest and the DEGRADED verdict are stdout `println!`; the 67-counter perf table is `-v`-only to stderr; the HTML report embeds seven summary fields (`export.rs:840-849`) — today's 18.5 MB report contains the string "backoff" zero times. `doh_failure_log` (per-provider counts) exists in memory and is never read back.

**6. Prior design constraints this plan honors (do NOT re-propose):** per-provider DNS buckets and hedged UDP racing (vetoed — multiply egress, ISA:1337), DoQ/DoH3 (dependency surface), CT rate-pacing gates (falsified 0/17→1/51, ISC-510), external scan-safety wrappers (owner directive 07-18). Preserve: DNS_NAME/DNS_ENDPOINT/DNS_THROTTLE split; all-providers-implicated breaker mask; IP-literal DoH endpoints; the UDP/53 shed ceiling's compile-time assert; DoH-scoped connection pooling. Binding process rules (repo CLAUDE.md): constants ship field-measured or as ≥5–10× backstops with probes; recall-sensitive changes get their validation scan BEFORE merge; bulk edits get per-hunk review.

**7. Open items this plan absorbs** (so they stop being lost): the d646b7c 48% residual; TF-DNS-REPRO (harness never committed); TF-DNS-FLOOD-PROTECTION's unbuilt half (subfinder resolution through DoH); `Plans/analyze-the-latest-npf-replicated-reddy.md` Steps 4 & 7 (subprocessor-budget↔DNS decoupling; ladder timeout correctness — untracked, unreferenced, effectively lost); dnsLayer.7 (fast path has no timer); ISC-513's not-done half (per-terminal-failure counting); TF-OBSERV (DNS failures never logged); P2.10a's gate.

**8. The unifying mechanism (verified in source after the audits).** `send_gated` is `gated(connection_semaphore(), self.send())` (`http_client.rs:280`): `self.send()` is evaluated — and reqwest fixes its 3 s timeout deadline — *before* the semaphore is awaited, so a DoH attempt can time out having never sent a byte. And `direct_txt_outcome` wraps `with_connection_permit(resolver.txt_lookup(..))` *inside* its 4000/2000 ms DoT/UDP budget (`dns.rs:825-828`, `:866-871`; system resolver `:2768`), with the code's own comment calling a budget overrun "the blocked/rate-limited-transport symptom." **All three DNS tiers queue behind 30 s subprocessor fetches and 120 s subfinder HTTP in one 128-permit FIFO.** That is how every tier can be declared dead in one run while each is healthy at idle, and why an isolated-subsystem bisect was clean.

## Approach — four phases, each gated on evidence

```
Phase 0  INSTRUMENT + PERSIST   (no behaviour change)  → PR-0
Phase 1  REPRODUCE + LOCALIZE   (matrix on owner's net) → data, no code
Phase 2  FIX at the root        (3 waves, each scan-validated BEFORE merge) → PR-1..3
Phase 3  GATE                   (hermetic simulator + mechanism tests + canary + scan rule) → PR-4..5
```
Rule 7 of the Algorithm (reproduce before fixing) and repo CLAUDE.md (scan before merge for recall-sensitive change; constants field-measured or ≥5–10× backstop with probe) are both binding, so Phase 1 precedes Phase 2 and every Phase-2 wave carries its validation scan in the PR body. Phase 3's hermetic layer lands *with* Phase 0 so the baseline numbers of the broken code are recorded in-repo before any fix.

## Phase 2 — Fix at the root (three waves; each PR carries its Layer-2 falsifiers + validation-scan probe block; merge order = leverage)

**Wave 1 — stop manufacturing congestion (changes 1, 2, 4, 5 + change 3's classification half):**

1. **DNS transports leave the shared connection semaphore; the governor IS the DNS connection ceiling.** (C primary; feeds A, B, G.) `dns.rs:1385`, `:1509` `.send_gated()`→`.send()`; remove `with_connection_permit` at `:827`, `:868`, `:2768`; `http_client.rs:284-290` + module doc rewritten; compile-time guard `assert!(DEFAULT_MAX_LIMIT as usize <= DEFAULT_MAX_CONNECTIONS / 2)`. Invariant: no DNS budget contains a wait on a non-DNS resource; peak DNS sockets ≤ governor.limit + 12 DoH idle + 3 DoT + 3 UDP. Falsifier: unit — `init_connection_ceiling(1)` held by `pending()`, wiremock DoH lookup completes; field — `dns.doh_attempt_timeout` and `ladder_descent{no_response}` drop while `http.conn_permit_wait` still shows saturation. Risk: recall none; sockets +≤64 over measured "low hundreds", guarded by the assert.
2. **The resilient loop owns its deadline; per-attempt budget = max(fair slice, measured RTO); every attempt observed; no sleeps on rotation.** (A primary; E cancelled-uncounted; G.) `dns.rs:1638-1716`, `:1762-1829`: `deadline = now + DOH_LOOKUP_DEADLINE (=existing 3 s)`; per attempt `budget = governor.rto().map_or(remaining/attempts_left, |rto| rto.max(remaining/attempts_left)).min(remaining).min(server cap)`; `rto()` = `rtt_recent + 4·rtt_var` (new Jacobson `rtt_var_us` in governor, RFC 6298 β=0.25/K=4 — estimator parameters, not sized ceilings, shipped with `dns.doh_attempt_timeout` probe). Remove `in_race_backoff` sleeps (`:1701-1705`, `:1816-1820`). Outer wrappers (`:2044`, `:2283`, `:2858`, `:2625`) become `4× deadline` hang backstops with probe `dns.deadline_backstop_fired` (expected 0). New class `DNS_TIMEOUT` mapped to `DnsOutcome::TimedOut` in `classify_pair` (`:611-640`, typed `reqwest::Error::is_timeout()` via `err.chain()`, fixes F) and `failure_outcome_for_governor` (`:653-658`); deadline-exhausted = one logical `dns_failures` (today zero; root-CNAME arm `:2917-2927` is a silent `Ok(vec![])` — visibility-contract violation, fixed). Falsifier: wiremock provider-1 hangs 2.5 s, provider-2 answers 50 ms → `Ok` inside 3 s; all-slow 1.2 s with seeded RTT≈1 s → first attempt gets ≥1.2 s and succeeds. Risk: recall +, speed + (no sleeps), load ≤ today.
3. **(classification half)** Typed `TransportEvidence {Responded, Unreachable, NoResponse}` from `reqwest::Error` (`is_timeout`→NoResponse; `is_connect`+io ConnectionRefused/Reset/NetworkUnreachable/HostUnreachable or TLS→Unreachable; connect-timeout→NoResponse; body/decode→Responded) and `NetError` (next to `net_error_is_authoritative_negative` `:756-758`: Io/Rustls→Unreachable; Timeout/NoConnections/Busy/Proto→NoResponse; Dns→Responded). `DirectOutcome::TransportFailed(TransportEvidence)`. **DNS_THROTTLE becomes `doh_health.record_success()`** (`:1682-1686`, `:1800-1804` — a 429/5xx is proof the transport delivered).
